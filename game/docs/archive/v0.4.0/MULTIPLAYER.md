# 联机启动与边界

## 私人本机 / 局域网

```
node server/server.cjs
node server/server.cjs --host 0.0.0.0 --port 8787
```

第一行仅监听本机；第二行用于房主明确开放私人局域网。服务器只使用 Node.js 内建模块，不需要 npm 安装。浏览器从服务器自身HTTP地址打开 `web/index.html`，UI会自动选用该地址的WebSocket服务。

创建者选定国家、地图、参战数、队伍模式和迷雾（双层/单层/无迷雾）。迷雾规则写入房间并在开局后锁定，客户端设置不可绕过。房间码生成后其他人加入。非房主必须点准备，然后房主开始。空位在开局时填充AI。4对4按0至3对4至7固定席位分队，合作模式把全部真人置于同一队。没有独立出生点和队伍拖放编辑器。

## 实际连接限制

已测：同一机器的两个独立WebSocket客户端，以及两个完整浏览器页面创建 / 加入 / 准备 / 开始。

未测：两台真实机器的局域网、防火墙配置、公网服务器、8真人同时在线、跨洲延迟、带宽受限与断线压力。测试环境记录在 TEST_REPORT.md。

朋友从另一台电脑连接时，请使用房主终端输出的局域网IP。双方不是同一可达网络时，房间码本身没有作用。

## 私人服务器安全说明

服务器默认监听127.0.0.1。提供有限的报文大小、序号、席位权限、构造 / 建造和沙盒指令校验，拒绝未支持的WebSocket帧类型。它并不是面向互联网的完整安全审计产品。

不要把私人原型无保护地暴露到公网。没有账户认证、公共服务容量控制、TLS证书管理、防DDoS、持久化房间和自动运维。确实部署在自有服务器时，需要另外配置同源HTTPS / WSS反向代理、访问认证与连接限制，并自行测试。静态HTTPS页面不能混连不安全的 ws:// 地址，应同源使用 wss://。

代码未内置任何公共服务器、内网穿透服务、账号、支付或分析上报。

## 掉线与结束

已连接但掉线的单位继续执行已存在的命令，不立即由AI接管。没有人连接时房间暂停，并在5分钟后清理。服务端支持带凭证的协议恢复，测试工具验证了席位恢复，但客户端暂未提供自动重连UI。关闭服务器即结束所有内存中的对局。

## 错误

- 地址被占用：换端口，例如 `--port 8788`，浏览器地址也同步修改。
- 版本不匹配：客户端和服务器必须来自同一个发行包。
- 返回403：确保浏览器页面与WebSocket为同一个服务器来源；直接打开离线HTML的空Origin也允许。
- 客人不能开始：由房主开始，其他人先准备。

## 0.3.0同步变化

客户端和服务端协议版本为3，旧0.2.0客户端不能加入。路径提交、追加、停止、主工厂、集结路线和生产右键操作均由服务器校验。建筑放置使用统一格子逻辑；新增commandResult回应，但不包含完整自动重连功能。

除自己的单位之外，可见单位快照不带其命令目标、路径队列或集结点。双层迷雾对建筑和矿区发最后一次可见记忆，不发当前隐藏血量或矿量。测试仅覆盖本机回环连接，详见TEST_REPORT.md。


## 0.4.0镜头设置

右键拖图、缩放、边缘滚屏和镜头设置都是本地行为，不会发出战斗命令或控制他人的镜头。打开设置不会暂停服务器。协议保持为3；为避免不同发行资产或UI行为混杂，各端仍应使用同一份0.4完整包。Windows独立窗口启动器本身不启动联机服务。
