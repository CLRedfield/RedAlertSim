# 用户体验审查与更新 · 0.4.0

本次基于0.3.0完整源码增量修改。主题是镜头难以移动、鼠标手势冲突和界面区域边界，未借这次更新改动战斗平衡或替换美术资产。

## 找到的问题和实际处理

| 旧问题 | 本次处理 | 有意保留的边界 |
| --- | --- | --- |
| 平移主要依赖中键/边缘，不符合用户长按右键习惯 | 长按或明确右拖启用镜头，短按保留原功能；中键保留 | 右键短按在松手时确认，这是手势区分所需的小变化 |
| 相同右键要承担下令、取消和拖图，容易冲突 | 指针手势单一仲裁，拖图后的松手不再调用世界点击 | 生产栏、小地图各自的右键含义保持不变 |
| 远距离移动反复抬鼠标 | 抓取与偏移控制速度的持续滚屏，两种可选 | 不强制光标锁定，抓取仍受屏幕边界约束 |
| 固定滚屏速度，斜向、帧率可能影响手感 | CSS像素/秒、归一化方向键、速度设置、平滑起步、立即停止 | 主线程卡顿不是换成原生窗口就必然解决，未承诺目标GPU帧率 |
| 画布底部藏在HUD后面，滚屏边缘不容易触达 | 战场单独划定边界；HUD、侧栏和弹窗不触发边缘滚屏 | 框选时不自动边缘滚动，避免误滚 |
| 滚轮总向中心收缩，需要反复找回目标 | 鼠标锚点缩放，处理不同滚轮事件单位，可关闭锚点和平滑 | 地图边界约束时锚点不保证绝对不动 |
| 操作感与鼠标硬件不同，却没有细调入口 | 可调方向、长按、抓取灵敏度、滚屏、边缘和缩放；三套起点预设 | 默认不是已对照的原版键位/镜头规则 |
| 切出窗口、丢失捕获后容易残留拖动 | resetPointer集中释放；事件取消、失焦、隐藏、弹窗和resize清理 | 切出窗口取消未提交路径，沿用0.3规则 |
| 缺少镜头状态和快速归位 | 右拖状态提示、起点标记、Home/End、VIEW工具条、全屏入口 | Home仅定位，不是持续跟随 |
| 希望接近软件窗口体验 | 增加Windows应用窗口启动器，优先Edge再Chrome | 不是原生EXE，Windows未实机验证，不捆绑运行时 |

## 测试发现并修复的实现问题

渲染器相机矩阵改为统一syncCamera时，一处阴影计算仍使用原局部aspect；已恢复局部变量并通过整页渲染检查。参数归一化明确只读取对象自身属性，避免继承属性混入偏好。

新联机镜头测试最初把两个真人都设置在合作队伍且没有敌方，游戏立即结算、结果弹窗正确阻止了拖图。测试改成有敌对关系的自由混战后验证了真实镜头行为；没有关闭游戏结算或绕过UI阻断来制造通过。

部分早期浏览器运行被容器单次工具时限终止；最后结果以完整执行并写出的JSON为准，不把中途终止记录为通过。浏览器原版操作回归有一次瞬态队列断言超时，之后单独重跑完整脚本通过。完整测试场景与局限见TEST_REPORT.md。

## 保持不变的范围

保留0.3的碾压、路径点、方格建造、快捷键、三种迷雾、主厂/集结和生产暂停取消。没有重新平衡价格、伤害、移动速度或AI。本轮唯一战场存档入口变化是允许读取结构兼容的0.3存档；通过原0.3生成的存档夹具验证。

不新增网络镜头报文，协议仍为3。服务器继续权威计算战斗，镜头只改变本地表现；正式房间迷雾仍由房主在开局前锁定。

## 下一轮仍值得解决，但本轮未冒充已完成

高优先是拥堵时的让路与卡路反馈、矿车闲置/矿区耗尽的可操作提示、网络断线的明确恢复入口。其次是可调UI比例、可配置提示等级、快捷键冲突的更完整引导、从战场诊断具体命令失败原因。

桌面客户端的完整路线还需要独立打包运行时、Windows实机验证、签名/更新机制、焦点与光标管理测试。这次的应用窗口入口只改善打开方式，不代替这些工作。完整原版单位、美术和机制差异仍见KNOWN_DIFFERENCES.md。

## 实现位置

`web/src/camera.js`：手势状态、按时间滚动、缩放、参数归一化。

`web/src/app.js`：Pointer Events、短按/拖图仲裁、localStorage、全屏、镜头菜单、定位按钮。

`web/src/renderer.js`：同步相机矩阵、世界投影与屏幕平移。

`web/template.html` / `web/style.css`：镜头面板、区域布局、拖动提示和自适应。

`tests/camera.test.cjs` / `tests/browser_camera.py`：数值与实际整页交互回归。
